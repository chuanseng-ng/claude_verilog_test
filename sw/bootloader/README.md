# sw/bootloader -- UART boot-ROM bootloader (bead `hlrm.2`)

The FPGA prototype boots from a small UART bootloader that lives in the 4 KB boot ROM and loads
programs into main SRAM, so changing firmware never needs a new bitstream. The bootloader is
**1620 bytes** of the 4096-byte ROM (39.6 %); `make size` fails the build above 4096.

| Part | File |
| ---- | ---- |
| Bootloader | `uart_boot.c`, `crt0.S`, `bootloader.ld.in`, `bl_config.h` |
| Wire protocol (shared C / Python / tests) | `uart_boot_proto.h` |
| Host loader | `tools/fw/uart_load.py` (pyserial) |
| Test payload | `testprog.c`, `testprog.ld`, `testprog_table.inc` |
| Committed images | `prebuilt/uart_boot_<variant>.hex`, `prebuilt/testprog.{bin,hex,elf}` |
| Tests | `tb/tests/test_uart_load.py` (host tool), `tb/cocotb/soc/test_uart_boot.py` (`make soc_uart_boot`) |

## Using it

```bash
# 1. FPGA build: point boot_rom at the image (the other agent's MEM_INIT_FILE wiring)
#      MEM_INIT_FILE = sw/bootloader/prebuilt/uart_boot_default.hex
# 2. Load and run any program linked at/after 0x2000
python3 tools/fw/uart_load.py /dev/ttyUSB1 firmware.elf            # ELF: segments + entry from the file
python3 tools/fw/uart_load.py /dev/ttyUSB1 firmware.bin --addr 0x2000
python3 tools/fw/uart_load.py /dev/ttyUSB1 --info                  # ping: version, block size, load window
```

Options: `--no-jump` (load only), `--no-verify`, `--chunk N`, `--retries N`, `--baud`.
Reset the board (or press the SoC reset) to get back to the bootloader.

Firmware must be **linked into the load window** reported by `--info`: `0x2000` up to
`0x2E00` with today's 4 KB SRAM (`sw/bench/rv32i.ld` links at `0x2000` but assumes a larger SRAM;
use a smaller `LENGTH`/stack until `SRAM_MEM_WORDS` grows).

## Regenerating the hex for `MEM_INIT_FILE`

```bash
nix develop <repo>#bench --command make -C sw/bootloader prebuilt    # rebuild + refresh prebuilt/
nix develop <repo>#bench --command make -C sw/bootloader check       # prebuilt/ == fresh build?
```

`boot_rom` reads the image with `$readmemh`: one 32-bit little-endian word per line, word *i* at
`0x1000 + 4i`, produced by `sw/bench/bin2hex.py` from `objcopy -O binary` of the ROM section.
The committed `prebuilt/` copy exists so that the cocotb suite and the FPGA flow need no RISC-V
toolchain (provenance: committed, regenerated by `make prebuilt`; `make check` detects staleness).

Variants (all built by default; each gets `build/<v>/uart_boot.{elf,bin,hex,dis,sym,map}`):

| Variant | UART clock / baud | `UART_BAUD` | Notes |
| ------- | ----------------- | ----------- | ----- |
| `default` | 50 MHz / 115200 | 26 | the FPGA plan: **use this for `MEM_INIT_FILE`** |
| `asic40` | 40 MHz / 115200 | 21 | Sky130 SoC, 25 ns period (`BL_UART_CLK_HZ=40e6`) |
| `sim` | divisor 5, 1 MHz "CPU clock" | 5 | cocotb: short bit times and short timeouts |
| `sim_auto` | `sim` + 5 ms auto-boot | 5 | cocotb: auto-boot fallback test |

Override anything in `bl_config.h`, e.g. a 100 MHz fabric clock and 921600 baud:
`make EXTRA_DEFS='-DBL_UART_CLK_HZ=100000000u -DBL_CPU_HZ=100000000u -DBL_BAUD=921600u'`.
A larger SRAM: `make SRAM_BYTES=65536` (the SoC's `SRAM_MEM_WORDS` must match; the linker script,
load window and `INFO` reply all follow).

Baud: the UART divides by `16*(D+1)`; `D = round(f_clk / (16 * baud)) - 1`. 50 MHz/115200 gives
D=26 -> 115741 baud (+0.47 %). 40 MHz/115200 gives D=21 -> 113636 baud (-1.4 %), inside 8N1 tolerance.

## Memory layout

```
0x0000_1000  boot ROM:  _start, .text, .rodata        (RESET_PC; 1620 of 4096 bytes used)
0x0000_2000  SRAM:      load window  [0x2000, 0x2E00)  <- WRITE targets, JUMP entries
0x0000_2E00  SRAM:      bootloader .bss + receive buffer + stack (512 B, top of SRAM)
0x2000_2000  UART       (MMIO, uncached)
```

`.data` is rejected at link time (nothing copies ROM to RAM), `.bss` is zeroed by `crt0.S`, and the
stack gets at least 128 B (linker `ASSERT`s). The bootloader RAM is **never** writable through the
protocol (`WRITE` to it NAKs `ADDR`), so a bad image cannot overwrite the loader that is loading it.
After `JUMP` the whole SRAM, including that region, belongs to the program.

## Protocol

Chosen for a UART that has **no hardware flow control and a 4-entry RX FIFO**, a CPU with no
M extension and a 4 KB ROM:

- **Binary framing + CRC32, not Intel HEX / SREC.** Parsing ASCII hex needs a line state machine,
  hex decode, per-record checksum and address-extension records (~1-2 KB of ROM here), and doubles
  the bytes on the wire. A length-prefixed frame needs ~30 bytes of CRC code and is trivial to script.
- **One ACK/NAK per frame** gives flow control: the host never has more than one block in flight, and
  the target writes SRAM only after the whole frame's CRC is good, so no bad data ever lands in memory.
- **CRC32 (IEEE 802.3, = `zlib.crc32`)**: a free host implementation, strong enough for any burst on a
  UART link. It is computed with a 16-entry nibble table (64 B, not the 1 KB byte table); one byte costs ~tens of cycles, far below
  the 4340 cycles a byte takes at 50 MHz / 115200.
- **Target-side CRC command** gives end-to-end verification of what actually sits in SRAM.

Host -> target (little-endian):

```
SOF 0x7E | CMD | LEN_LO LEN_HI | PAYLOAD[LEN] | CRC32[4]      CRC32 over CMD, LEN, PAYLOAD
```

Target -> host: `ACK 0x06, N, PAYLOAD[N]` or `NAK 0x15, ERR`.

| CMD | Payload | ACK payload | Notes |
| --- | ------- | ----------- | ----- |
| `0x01 INFO` | none | version (1), max data (u16), load_lo (u32), load_hi (u32) | ping / discovery |
| `0x02 WRITE` | addr (u32) + 1..128 data bytes | none | byte stores; any alignment |
| `0x03 CRC` | addr (u32), nbytes (u32) | crc32 (u32) | flushes + invalidates the D$ first so it reads SRAM, not cache |
| `0x04 JUMP` | entry (u32, word-aligned) | none | ACK, drain UART TX, clean D$, `FENCE.I`, call entry |

| ERR | Meaning |
| --- | ------- |
| `0x01` | bad CRC |
| `0x02` | unknown command |
| `0x03` | bad length (wrong for the command, or larger than the receive buffer) |
| `0x04` | address outside the load window (ROM, MMIO, bootloader RAM, straddling or wrapping) |
| `0x05` | idle timeout in the middle of a frame |

Boot banner (informational): `"\nUBL1\n"`. Bytes arriving outside a frame are ignored (line noise,
bytes sent before the loader was ready).

### CRC check

The target does not buffer the 4 received CRC bytes. It folds them into the running CRC register
after the payload; a correct frame always leaves the register at the constant residue `0xDEBB20E3`
(the CRC-32 "magic check value" before the final inversion). `test_uart_load.py` proves the
residue for random frames and that any single-bit flip breaks it.

### Error recovery

The target cannot know where a damaged frame ends, so recovery is timing-based:

1. A frame that arrives complete but with a wrong CRC is NAKed immediately; nothing is written.
2. If bytes stop mid-frame for `BL_IDLE_MS` (20 ms) the target NAKs `TIMEOUT` and returns to hunting for `SOF`.
3. After a NAK `CRC`/`LEN`/`TIMEOUT` or no answer at all, the host waits longer than that idle timeout
   (default 60 ms), discards its input, and re-sends (`--retries`, default 3). A false `0x7E` inside
   a damaged payload is thereby swallowed by the idle timeout instead of poisoning the next frame.
4. `ADDR`/`CMD` NAKs are clean refusals and are never retried.

## Boot flow and the timeout fallback

Reset -> `UART_BAUD`/`UART_CTRL` set -> banner -> wait for frames. **By default
(`BL_AUTOBOOT_MS=0`) the bootloader waits for the host forever**: SRAM comes up empty after an FPGA
configuration, so there is nothing safe to fall back to.

Optional auto-boot (`-DBL_AUTOBOOT_MS=N`, tested by the `sim_auto` variant): if **no byte at all** is
received within N ms after reset, jump to `BL_AUTOBOOT_ADDR` (default `0x2000`) **provided the word
there is neither 0 nor `0xFFFFFFFF`**; otherwise keep waiting. Any received byte cancels the window.
That suits warm resets where SRAM still holds the last image, or a flow that preloads SRAM from a
debug bridge. Timeouts count the `mcycle` CSR, so `BL_CPU_HZ` must be the CPU clock.

## Cache hand-off (Phase 3 / MMIO-decision coherency rules)

Software-managed coherency, no hardware snooping (`docs/design/PHASE5_MMIO_UNCACHED_DECISION.md`):
SRAM is cacheable and the D$ is write-back, so freshly loaded code is dirty in the D$ and invisible
to the I$ path. `JUMP` therefore:

1. waits for the ACK/UART TX to drain,
2. `fence` + `csrw 0x7C0, x0` (**dcache_flush**: write back every dirty line) + the same 2048-iteration
   drain spin `sw/bench/crt0.S` uses,
3. `FENCE.I` (raw word `0x0000100F`, because `-march=rv32i_zicsr` has no Zifencei) to invalidate the I$,
4. calls the entry point.

The D$ needs no invalidate on this path: after the flush its lines equal SRAM. `CRC` additionally
issues `csrw 0x7C1, x0` (**dcache_inval**) after a flush so it reads SRAM itself. Nothing may store between the flush and the invalidate (the invalidate drops dirty lines), so both run in one register-only asm block; an earlier C version with a `volatile` spin counter rolled back its own stack and hung. UART registers are
in the uncached MMIO window, so they need nothing.

## Build notes

- `-march=rv32i_zicsr -mabi=ilp32 -Os -ffreestanding -nostdlib`, **no libgcc**: any multiply/divide
  or `memcpy` the compiler emitted would be an undefined reference and fail the link. All
  `BL_*` arithmetic is compile-time.
- `-fno-tree-loop-distribute-patterns -mno-relax -msmall-data-limit=0`: no hidden `memset` calls, no
  `gp`-relative addressing (the ROM start-up sets only `sp`).
- The test payload is built with the same flags and linked at `0x2000` (`testprog.ld`).

## Verification (no board)

`make -C tb/cocotb/soc soc_uart_boot` loads the real image into `u_boot_rom.mem` of `tb_soc_top`,
and drives `uart_rx_i` / decodes `uart_tx_o` with bit-level UART models, covering: banner + INFO at
the shipped D=26 divisor and at the simulation divisor; a 436-byte program loaded in four blocks,
CRC-verified, started with `JUMP` and observed running (UART signature `PAYLOAD OK 106B0960`, entry PC
`0x2000` committed, SRAM contents equal to the image); bad CRC (in the CRC field and in the payload),
ROM/MMIO/bootloader-RAM/straddling/wrapping addresses, unknown command, wrong lengths, misaligned or
ROM `JUMP`, truncated frame, oversized length, line noise before `SOF`; and auto-boot with and without
a preloaded image. `tb/tests/test_uart_load.py` covers the host tool and CRC convention without a
simulator.

**UART RX framing (bead `shm5`, fixed in RTL).** `uart_controller`'s receiver used to return to
`RX_IDLE` only at the *end* of the stop bit (`bit_tick`) and then re-align on the next oversample
tick, so after every back-to-back 8N1 byte it was one oversample tick (`D+1` clocks) later relative to
the sender; after about 7 bytes without idle time the mid-bit sample point crossed a bit boundary and
the byte was mis-framed (an 8-byte INFO frame at 1 stop bit failed, with 2 stop bits it passed). The
receiver now has its own phase counter that restarts on **every** START edge, votes each bit on phases
6/7/8, and closes the frame at the stop-bit mid-point (push byte, framing check, re-arm), so the next
START is accepted from there on. Plain **8N1 with no idle gap works**, at a sender bit-clock error of
up to +/-3.5 % (`test_uart.py::test_rx_back_to_back_*`: 256 zero-gap bytes, +/-2 % and +/-3.5 %, 8N2;
`soc_uart_boot::test_load_verify_8n1_back_to_back`: a full program load at 8N1). **8N2 stays the
host-loader default** (`uart_load.py`, the cocotb UART model): it costs 10 % throughput (11 bits per
byte) and buys one extra bit time of idle margin; `uart_load.py --stopbits 1` selects 8N1. No firmware
or boot-image change was needed: the bootloader only reads bytes from the RX FIFO.

**Receive-rate headroom (measured in simulation).** Each received byte costs two MMIO reads that cross
the CPU -> fabric bridge. At divisor 3 with 8N2 (704 clocks/byte) the bootloader keeps up (128-byte
WRITE frames ACKed); the shipped 50 MHz / 115200 setting gives 4774 clocks/byte, a >6x margin.

**Not covered (needs the board):** real USB-UART timing and latency, and receive FIFO overrun with a
host that ignores the per-frame ACK.
