# Innovus b5h (interim status, 2026-10-31)

Changes vs b5g (physical setup identical: b5f/b5g env B5C_SCREEN B5D B5F, same netlist, die/core, SRAM placement, pins, PDN):
1. `set_ccopt_property update_io_latency false` (property verified: "Determine whether to update IO latencies within ccopt_design", default true). No hidden `set_clock_latency -source` is written.
2. Symmetric SDC-visible I/O latency: virtual ideal clock `clk_io` (same construction as `sky130_cpu_iolat.sdc`), source latency 1.0, network latency = measured mean clock insertion delay after CTS = **3.295 ns** (Avg ID of the early skew-group row; b5g Innovus had applied 2.909 rise / 2.652 fall). Generator `pnr/commercial/constraints/gen_innovus_io_sdc.py` (shared SDC unchanged, md5 3c69...). Pre-CTS file `sky130_cpu_innovus_pre.sdc` (clocks ideal, no network latency).
   Finding: Innovus stores SDC clock latencies in the view `latency.sdc` and re-applies it AFTER the SDC on restore/update, so `update_constraint_mode` alone leaves clk_io at the stale network latency 0 (first attempt: I/O hold -3.7 ns, hold buffers inserted for nothing). Fixed by `set_clock_latency $LIO [get_clocks clk_io]` in the interactive constraint mode right after the update; verified in the path report (`Network Insertion Delay 3.295`, reports/b5h_spot_input_hold_postcts.txt).
3. Cap table for rc_nom: `impl/innovus/captbl6/sky130A_nom_li1m1.captbl` from the tuned ICT (calibrated to OpenRCX, not silicon). generateCapTbl treats the conductor `li1` as the POLY-class layer and emits M1..M5 = met1..met5 while the tech LEF has six routing layers, which is why the old table was rejected (IMPEXT-3548). `scripts/mk_ict_li1m1.py` renames li1 -> met0 in the ICT, giving M1=li1..M6=met5; Innovus accepts it (rc_nom "Cap Table" loaded in every stage). Generation 56 min. nom only (min/max not generated; the Innovus flow is tt-only).
Measured so far (Innovus native, tt, capTable RC, SI-aware): 04_cts post-opt setup +0.013 / hold +0.002 (hold-fix on unconstrained mbist inputs); 05a_route DRC 0, antenna 23; post-route-opt setup WNS +0.215, hold WNS +0.139 (reg2reg +0.139), antenna 1, no repeater repair (b5g 05g/05h not needed: the long-AXI-net failure did not reproduce).
