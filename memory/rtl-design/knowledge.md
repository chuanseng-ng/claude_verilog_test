# RTL Design Knowledge Base — RV32I SoC Project

## Known Failure Patterns

- **Async reset maps to DFFASRHQNx1 on ASAP7, adding 60–120 ps per FF on critical paths.** The `negedge rst_n` clause forces the slow QN output path and increases async-reset load. Fix: convert every `always_ff @(posedge clk or negedge rst_n)` block to `@(posedge clk)` with synchronous reset — maps to DFFHQx1. Files confirmed safe (no async FFs needed): `rv32i_pipeline_wb.sv`, `rv32i_hazard_unit.sv`, `rv32i_interrupt_ctrl.sv`. Files requiring conversion: `rv32i_icache.sv`, `rv32i_dcache.sv`, `rv32i_cache_arbiter.sv`, `rv32i_pipeline_if.sv`, `rv32i_pipeline_id.sv`, `rv32i_pipeline_ex.sv`, `rv32i_pipeline_mem.sv`, `rv32i_core.sv`, `rv32i_csr_file.sv`, `rv32i_regfile.sv`, `rv32i_cpu_top.sv` (APB debug registers). (confirmed across 3 runs)

- **High-fanout combinational signals cause hundreds of picoseconds of setup loss on ASAP7.** Three confirmed instances: D-cache `hit` signal (821 fanout loads, −800 ps WNS); I-cache `tag_web0` write-enable (298 fanout loads); forwarding-mux select cone from hazard unit (~18 gates). Fix pattern for all three: register the signal one cycle before the SRAM/FF consumers, then replicate into per-bank copies with the `(* keep=1 *)` synthesis attribute to prevent the tool from merging them back. D-cache fix adds one stall cycle for cache hits (3→4 stall cycles total). I-cache fix delays `valid_array` set by one cycle to match the registered tag write.

- **Deep combinational EX-stage cones are the dominant ASAP7 critical path across every run.** A ~20–22-gate ALU + trap-encode + byte-align + forwarding-mux chain from the id_ex_reg FF to the next pipeline register causes WNS in the −700 to −800 ps range. Mitigation sequence used across Runs 11–31: (1) insert EX2 post-register stage to cut ALU result path; (2) split EX into EX1a (ALU + priority trap encode) + EX1b (flat `unique case` dispatch) with FF boundary between them; (3) pre-encode trap dispatch into `dec_*` fields in EX1c so EX1b becomes single-gate direct assigns; (4) pre-register forwarding selects in hazard unit one stage early (no clock-enable — must update during stalls so stall-exit sees correct selects). Each FF boundary insertion increases branch misprediction penalty by one cycle; track cumulative penalty carefully when stacking fixes.

- **GPU `mem_busy` gating on `id_ex_q.iclass==IC_MEMORY` causes premature pipeline unstall.** When a VST instruction advances from EX to EX/WB and a VRET occupies EX, `id_ex_q.iclass` is `IC_VRET`, so `mem_busy` drops to 0 one cycle early. The pipeline unstalls, VRET fires `warp_done`, and `kernel_done_o` asserts before the AXI write completes. Fix: `mem_busy = mem_stall_i` — stall whenever the coalescer is in-flight regardless of the current EX instruction class. `mem_stall_i` (= `busy_q` in `gpu_memory_unit`) is already the precise coalescer-activity signal. File: `gpu_compute_unit.sv` line 178.

- **Inserting a purely-combinational EX1c stage between two FFs adds pipeline depth without timing benefit.** Run-20 experimented with EX1c as a combinational passthrough between `ex1a_ex1b_reg_q` and `ex1c_ex1b_reg_q`; this does not break any combinational cone because no new FF boundary exists. The correct approach is to either register EX1c output (adding a real FF boundary) or remove EX1c and treat `ex1c_ex1b_reg_q` as a pure retiming FF. Hazard and forwarding port names using the `ex1c_` prefix can remain valid even when the stage is collapsed to a wire-through FF.

- **EX2 retiming changes the load-use stall count and forwarding encoding.** Adding an EX2 stage means: (a) load result is available one cycle later → load-use stall may grow from 1 to 2 cycles; (b) the forwarding mux must extend from 3-way (01=EX/MEM, 10=MEM/WB) to 4-way (01=EX2, 10=MEM, 11=WB) requiring hazard unit rewrite; (c) `stall_ex_mem` port removed from EX since EX2 now owns the register. JALR redirect target and D-cache address consumers of `alu_result` must remain correct after the retiming boundary.

### CDC / reset-domain patterns (XDG-era, 2026-08-01 → 2026-08-13; folded with the old XDG-root knowledge file)

- **A reset value that advertises availability is the dominant CDC bug class here.** It showed up twice in GH #93. (1) `soc_top.sv` (`4398c2e`, `fr_57f49b7f9b29`): the CPU clock-gate enable went through `cdc_2ff_sync`, which always resets to 0, and 0 meant "clock disabled". `cpu_gated_clk` never ticked while `cpu_domain_rst_n` was low, so `u_cpu`'s synchronous reset never loaded `RESET_PC`. `async_axi_fifo`'s s-side `cdc_reset_sync` was starved the same way. Fix: synchronise the inverted sense (`~pmu_cpu_clk_en` into `pmu_cpu_clk_dis_sync`), so reset-to-0 means "not disabled". (2) `cdc_gray_fifo.sv` (`7a9f9d4`, `fr_280f3ac18c66`): see the next entry. General rule: when the primitive's reset value is fixed, pick the signal polarity so that reset value IS the consumer's safe state.

- **CDC handshake outputs must be gated by their OWN domain's reset, not just a flag register's reset value.** `wr_ready_o = !full_q` read 1 for the whole write-domain reset window, because `full_q` resets to "not full". A master could complete a handshake whose beat was silently dropped. This is reachable only when the two domains' resets release at different real times (independent PLL locks, asymmetric ratio), so it is invisible at 1:1. Fix: `assign wr_ready_o = wr_rst_n_i && !full_q;`, a same-domain AND with no new CDC path. `rd_valid_o` was already safe (`empty_q` resets to 1). `apb_cdc_bridge` is safe by construction: `s_pready_o` is gated by `s_state_q==S_DONE`, and the FSM resets to `S_IDLE`. Ask of every ready/valid output: "what does this read on the first cycle after MY reset releases while the peer may still be in reset?" Sweep sibling outputs. The fix flipped one `async_axi_fifo` unit test whose kill timing depended on the bug: a masked testbench race, not a new RTL defect.

- **Two independently synchronised control signals do not keep their source-side order downstream (bead `542`).** `pmu.sv` releases reset one `core_clk` before ungating the clock; the UPF requires this order. Reset crosses via `cdc_reset_sync` and clock-enable via `cdc_2ff_sync`, so a live PMU power-cycle could restart the CPU clock before reset release is observed and overwrite retained PC/MSTATUS/MTVEC. Fixed in `soc_top.sv`, NOT `pmu.sv` (its order is UPF-mandated): `cpu_gated_clk_en = ~pmu_cpu_clk_dis_sync & pmu_cpu_rst_n_cpu_sync`. Pattern: derive the dependent signal from the ALREADY-synchronised independent one, so the invariant holds by construction in the destination domain with unbounded skew tolerance. Residual: no suite runs a live PMU power-cycle at a divergent ratio; the argument is structural only.

- **Check a toggle-handshake bridge's reset coupling separately for each direction.** In `apb_cdc_bridge.sv` (PR #132, CodeRabbit), `rst_both_n = s_rst_n_i & m_rst_n_i` held the SOURCE FSM in `S_IDLE` during a destination-only reset. A held-in-reset FSM cannot even emit an error, so the whole fabric APB tree wedged. Fully decoupling both sides was rejected before implementation: an s-only reset after an odd number of transfers breaks the `req`/`seen` toggle-parity invariant. Adopted fix: the source reset is rooted on `s_rst_n_i` only; the destination stays on `rst_both_n`; a destination-in-reset status sync gates forwarding (`req_fwd_q`), bounds `S_WAIT`, and clamps the request toggle while the destination is in reset. The result is a bounded `pslverr=1`, not a hang. `test_reset_mid_transaction_m_side` encoded the old hang semantics and needed a verification-side update. The bridge was later rewritten to 4-phase RZ `req_q`/`ack_q` (bead `rfz`, 2026-08-12, per the pd `86a`/`je8` record), so check the current source before reusing these details.

- **Synchroniser polarity when chaining onto an already-synchronised reset.** A new `cdc_2ff_sync` reset by `s_rst_sync_n` adds its settle latency IN SERIES with the first sync. If its fixed reset value is the fault state ("presumed in reset"), every post-reset transaction pays both settle times. This only showed at the slowest ratio: `test_clock_ratio_slow_s_fast_m` at 18 ns / 4 ns failed txn 0. Fix: synchronise the active-high "peer in reset" sense (`~m_rst_n_i`), so reset-to-0 means "presumed alive". Re-run the whole ratio sweep after adding any status synchroniser.

- **An optimistic reset default is acceptable only when a second, non-optimistic signal covers its window.** `apb_cdc_bridge.sv` `m_rst_n_s` reads "alive" for exactly `SYNC_STAGES_TO_S` `s_clk_i` cycles while `m_rst_n_i` is low. That is safe because `m_rst_sync_n` (no such exception) holds the destination FSM in reset the whole time and `S_WAIT` exits within that bound. Document the invariant at the line, as was done in the module header and PR #132, so it does not look like an unexamined leftover. Flagged as a refinement for the GH #95 cdc_snitch check.

- **Unsynchronised APB crossing to a reference-clock block (GH #86).** `u_pll_sub` must run on raw `clk_i`/`rst_n_i`, because it SOURCES `core_clk`, while APB arrives from `axil_to_apb` on `core_clk`. Under `PLL_IMPL="RNM"` that crossing had no synchroniser. Fix: a third `apb_cdc_bridge` (`u_apb_pll_cdc`), copied from `u_apb_pll2_cdc`, instantiated unconditionally so the STUB regression exercises the same netlist (in STUB mode it only adds latency). Gating the bridge on `core_rst_n` cannot self-brick: `CONTROL[0]` pll_enable resets to 1 and is excluded from WMASK (GH #89 fix `110d7ac`). The SDC follow-up (bead `je8`) needs `set_max_delay -datapath_only` on `u_req_sync`/`u_ack_sync` and the 4 `cmd_*` / 2 `resp_*` payload buses, mirroring `u_apb_pll2_cdc`.

### Datapath / synthesis patterns (2026-09 → 2026-10)

- **Fan-out fixes must break both decode width AND physical distribution (bead `rvb`, `sram_controller.sv`).** A registered one-hot `word_sel_q` still left `s_wvalid` driving a MEM_WORDS-wide AND array, which stayed the #1 setup-violator class (16 400 violators, worst −1050.16 ps). Fix: a 3-stage write pipeline. Stage 1 is the input register, stage 2 is per-group local registers (fixed `GROUP_WORDS=32`), and stage 3 is the per-group `mem[]` write. A drain FSM state delays BVALID until the last beat has landed. A RAW bypass was not added because the CPU D-cache, GPU coalescer and DMA all wait for BVALID before a dependent read. Cost: the per-word `always_ff` array scales Verilator build time super-linearly (see the verification knowledge, bead `8yd`).

- **Yosys `opt_merge` silently re-merges identical replicated registers.** NGROUPS copies with the same D-input collapse back into one high-fanout register. Fix: a self-holding D-input (`grp_wdata_q[k] <= sel ? new_data : grp_wdata_q[k]`), so each copy is structurally distinct. Verify with standalone `opt -fast -full; opt_merge -share_all` (0 cells removed). This complements `(* keep=1 *)` above.

- **`apb4_register_bank` lets a SW write override a same-cycle HW write even with WMASK=0** (`f7vs.7` watchdog). A stray store to HW-owned RO words (COUNT/STATUS) stalls the counter or drops a set. Fix in the peripheral: present stores to RO words to the bank as reads (`bank_pwrite_w`). The same hazard is latent in the pwm/gpio IRQ_STAT registers.

- **The bank cannot protect a register dynamically.** NPU WADDR-write-while-busy rejection is done by gating `penable` into the bank for that one transfer, keeping the planned WMASK.

- **"No new runtime-indexed mux" (the `ma7` gate) must be checked per module on the coarse-grain netlist.** A full `synth` techmaps `$shiftx`/`$pmux` away, so a zero count proves nothing; use `synth -run :fine`. `apb4_register_bank` itself carries 4 `$shiftx` + 2 `$shift`, so a flat count is never 0; attribute per module without `-flatten`. Yosys `proc` lowers every `case`, including constant-label ones, to `$pmux`. For zero `$pmux`, use 2:1 ternary trees, one-hot AND-OR and positional shift registers. NPU result: 0 `$pmux`/`$mem` in `rtl/npu`. This method replaced the vacuous CRYPTO check (bead `f7vs.15`).

- **Check fix-request arithmetic against both ends of the spec (I2C `fr_609b42790e0f`).** The bit engine had 3 timed phases plus a 3-clock sync wait, giving 132.8 kHz at the documented 100 kHz and tHIGH 2.53 µs (min 4.0). "Add a 4th phase" with a symmetric 2N/2N split still gives tLOW 1.26 µs at CLKDIV=62 (min 1.3). Fix: a `S_BIT_HI1` state with HI1 reload `CLKDIV-(SYNC_STAGES+1)-K`, L2 reload `CLKDIV+K`, `K=floor(N/8)`. That gives 100.0 / 396.8 kHz. `ceil(N/8)` broke `test_i2c_clkdiv_clamp_to_min`, so it was reverted rather than editing the safety-net test. The protocol core was split into `rtl/periph/i2c_bit_engine.sv` (parent 999→701 lines). Prove a behaviour-preserving refactor with identical sim end-times and measured values, not only pass counts.

- **A new RTL file must be added to every file list, including ones inside tests.** For the I2C split that was 7 lists: 3 cocotb Makefile, 2 `pnr/Makefile`, 1 `sim/Makefile`, and 1 built inside `test_i2c.py`. The last was found only through a MODMISSING failure. `check_periph_filelists.py` exists for the Makefile lists. When negative-controlling a checker, confirm the mutation actually applied: a `cp` with a glob destination failed silently and `&&` skipped it.

## Successful Tool Flags

- **`(* keep=1 *)` synthesis attribute** prevents Yosys/the synthesiser from merging replicated registered signals back into a single net. Essential for all fanout-duplication fixes (hit_bank_q, refill_addr_bank_q, pre-registered forwarding selects).

- **Lint command**: `cd ~/Downloads/Github/librelane && nix-shell --run 'make -C /home/neuromorphic/Downloads/Github/claude_verilog_test/sim lint'`. Uses `sim/Makefile` VERILOG_SOURCES which includes the correct behavioral SRAM stub. Do not run Verilator with bare absolute paths outside nix-shell — the nix Verilator binary requires nix-shell for its stdlib dependencies.

- **`unique case` over `if-else-if` cascade** for trap-type dispatch. An 8-level if-else-if trap cascade creates a ~22-gate NOR5/NAND5 chain. Replacing with a flat `unique case(trap_type)` on a pre-encoded 3-bit enum reduces gate depth to ~1 level (mux select) per branch.

- **Behavioral SRAM stub for FreePDK45**: `rtl/mem/sram_1rw_256x32_freepdk45.sv` — create as a minimal behavioral model for lint purposes when the PDK macro is not in the RTL tree. Analogous stub for ASAP7: `sram_1rw_256x32_verilator.v` in the ASAP7 PDK directory.

- **Lint A/B against a git-stash baseline** (used in 3 XDG-era sessions): run `make -C sim lint` / `lint_soc` before and after and compare warning lists. A byte-identical warning set with 0 errors proves no new warnings. The `lint_soc` baseline has been 7 warnings (1 DECLFILENAME, 3 BLKSEQ, 3 UNUSEDPARAM) in Aug 2026 and 4 warnings in late Sep 2026; re-take the baseline rather than trusting a remembered count.
- **Scratch-dir cocotb diagnostics without touching `tb/`:** point the `tb/cocotb/soc` Makefile's existing `VERILOG_SOURCES` at a throwaway module in the scratchpad (`MODULE=<scratch>`, `PYTHONPATH` prepended). This adds debug logging with no risk to verification's uncommitted `tb/` work.
- **Coarse-grain netlist cell census:** `yosys ... synth -run :fine` (no `-flatten`) for per-module `$shiftx`/`$pmux`/`$mem*` counts. See the `ma7` entry above.

## PDK / Tool Quirks

- **ASAP7 flip-flop cell selection is reset-style-sensitive.** Async-reset FFs map to `DFFASRHQNx1` (QN output, higher load, +60–120 ps). Sync-reset FFs map to `DFFHQx1` (Q output, lower load). Always use sync reset for any FF on a timing-critical path.

- **FreePDK45 macro not in the RTL/Verilator search path.** The `sram_1rw_256x32_freepdk45` macro is PDK-only and not visible to Verilator lint. Create a behavioral stub in `rtl/mem/` for lint runs.

- **Verilator BLKSEQ warnings on cache array reset loops are pre-existing and intentional.** The `valid_array` and `dirty_array` bulk-clear patterns use blocking assignments inside `always_ff` for procedural invalidation — functionally correct. These 3 warnings appear in every lint run and should be ignored; they are not regressions.

- **Verilator DECLFILENAME warning on SRAM stub and UNUSEDPARAM on REFILL_BEATS** are persistent pre-existing warnings unrelated to any RTL change. Baseline warning count is 5 (3× BLKSEQ + DECLFILENAME + UNUSEDPARAM); any lint run with exactly these 5 warnings and 0 errors is clean.

- **yosys-slang strict mode rejects use-before-declare** (bead `q7n` precedent). New `logic` decls in `soc_top.sv` (e.g. the 6 Phase-6 IRQ ties, `f7vs.2`) must sit before first use, ahead of `u_ext_irq_sync`.
- **Verilator PINCONNECTEMPTY:** tie an unused macro output (e.g. SRAM `dout1`) to a named wire plus a reduction, not `.dout1()`.
- **Linting the ASAP7 arm against `pnr/asap7/sram_1rw_256x32_asap7_stub.v`** gives 6 UNUSED/UNDRIVEN warnings that belong to the empty blackbox stub, not to the RTL.
- **Verilator treats comment text containing "Verilator" as a directive.** Reword such comments (seen again in Phase 7 PLL integration).
- **sv2v part-select-of-function-call** must be grep-checked on new peripherals (`f7vs.7`).
